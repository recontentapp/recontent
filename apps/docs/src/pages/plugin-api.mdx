# Plugin API

A plugin is an object with a `name` and up to four lifecycle hooks. It receives the resolved tokens
and returns the files to write. Everything the built-in plugins do goes through this interface, so
you can add outputs the same way: a Swift or Kotlin file, a Style Dictionary JSON, a linter, an
icon sheet.

Types are exported from `recontent/plugins`:

```ts twoslash
import type {
  EmittedFile,
  PluginContext,
  PluginDiagnostic,
  RecontentPlugin,
} from "recontent/plugins";
```

## RecontentPlugin

```ts
interface RecontentPlugin {
  name: string;
  enforce?: "pre" | "post";
  buildStart?(ctx: PluginContext): void | Promise<void>;
  validate?(ctx: PluginContext): PluginDiagnostic[] | Promise<PluginDiagnostic[]>;
  generate?(ctx: PluginContext): EmittedFile[] | Promise<EmittedFile[]>;
  buildEnd?(ctx: PluginContext & { files: EmittedFile[] }): void | Promise<void>;
}
```

| Member       | Description                                                                                                                                    |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`       | Required. Namespaced, for example `"acme:a11y-contrast"` (built-ins use `recontent:css`). Used in logs, diagnostics and file-collision errors. |
| `enforce`    | `"pre"` runs the plugin before plugins without `enforce`, `"post"` after them. Within each group, the order of the `plugins` array is kept.    |
| `buildStart` | Called first, once per build, for every plugin.                                                                                                |
| `validate`   | Return diagnostics for problems you find. Any `"error"` aborts the build before anything is written.                                           |
| `generate`   | Return the files to write.                                                                                                                     |
| `buildEnd`   | Called after generation with the files of **all** plugins in `ctx.files`. Nothing has been written yet.                                        |

All hooks may be `async`. Each hook runs for every plugin before the next hook starts: all
`buildStart`s, then all `validate`s, then all `generate`s, then all `buildEnd`s. If a hook throws,
the build fails with the error's message and exit code `1`.

## PluginContext

| Field        | Type                             | Description                                                                                                                   |
| ------------ | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `registry`   | `Map<string, TokenEntry>`        | Every token, keyed by its dotted path (`"system.color.accent"`).                                                              |
| `themes`     | `Record<string, ThemeOverride>`  | Each theme's overrides: a `Map` from token key to the overriding value.                                                       |
| `root`       | `string`                         | Absolute path of the directory containing the config.                                                                         |
| `logger`     | `Logger`                         | `info`, `warn`, `error` and `debug` methods. All write to stderr.                                                             |
| `mode`       | `"build" \| "watch"`             | `"watch"` under `build --watch`, otherwise `"build"`.                                                                         |
| `components` | `ComponentManifest \| undefined` | The [component manifest](#componentmanifest). Set when the config has [`introspection`](/tokens/configuration#introspection). |
| `git`        | `GitInfo \| undefined`           | The [git state](#gitinfo) of the project. Unset outside a git work tree.                                                      |

A `TokenEntry` describes one token:

| Field                                        | Description                                                                               |
| -------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `path`                                       | `string[]`, for example `["system", "color", "accent"]`.                                  |
| `layer`                                      | `"ref"`, `"system"` or `"components"`.                                                    |
| `$type`                                      | The token type (`"color"`, `"dimension"`, …).                                             |
| `$value`                                     | The resolved value, shaped by `$type` (see below). For an alias, the value of its target. |
| `alias`                                      | `string[]`: the path of the token this one points at, if it is an alias.                  |
| `scale`                                      | Metadata of the [scale](/tokens/scales) the token belongs to, if any.                     |
| `$description`, `$deprecated`, `$extensions` | Metadata set with `.describe()`, `.deprecate()` and `.extend()`.                          |

Values are structured, never strings:

| `$type`                                                    | `$value`                                                                                                                |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `color`                                                    | `{ colorSpace, components, alpha, hex }`                                                                                |
| `dimension`, `duration`                                    | `{ value, unit }`                                                                                                       |
| `fontFamily`                                               | `{ value: string[] }`                                                                                                   |
| `fontWeight`, `number`                                     | `{ value: number }` (a name for `fontWeight` is possible: use the table in [Primitives](/tokens/primitives#fontweight)) |
| `cubicBezier`                                              | `{ value: [number, number, number, number] }`                                                                           |
| `strokeStyle`                                              | `{ style }` or `{ dashArray, lineCap }`                                                                                 |
| `shadow`, `border`, `transition`, `gradient`, `typography` | Objects whose members are `{ $value, alias? }`                                                                          |

To apply a theme to a token, check `ctx.themes[name].get(key)` first, then fall back to the entry's
own `$value`.

## ComponentManifest

`ctx.components` lets a plugin generate Storybook argTypes, Figma Code Connect stubs, MCP resources,
lint rules or a changelog without building a TypeScript program of its own. It is only computed when
the config sets `introspection`, so token-only projects pay nothing.

```ts
type ComponentManifest = {
  schemaVersion: "1";
  components: ComponentInfo[]; // sorted by name
  warnings: { message: string; component?: string }[];
};

type ComponentInfo = {
  name: string; // export name, "Tabs.Item" for subcomponents
  sourceFilePath: string; // posix, relative to the config root
  line: number; // 1-based, for source links
  history?: FileHistory; // when git is available
  description?: string;
  deprecated?: true | string;
  props: PropInfo[]; // declared in your project, sorted by name
  inherits: { name: string; package?: string; count: number }[];
};

type PropInfo = {
  name: string;
  type: string;
  values?: (string | number | boolean)[]; // when the type is a union of literals
  required: boolean;
  defaultValue?: string;
  description?: string;
  deprecated?: true | string;
};
```

All of these types are exported from `recontent/plugins`. See [`introspection`](/tokens/configuration#introspection)
for how components and props are found.

## GitInfo

```ts
type GitInfo = {
  commit: string; // HEAD
  branch?: string; // unset on a detached HEAD
  dirty: boolean; // uncommitted changes under the config root
  shallow: boolean; // dates from history may be wrong
  root: string; // the config root relative to the git root, "" at the top level
  remote?: { url: string; webUrl?: string }; // origin; webUrl for GitHub, GitLab and Bitbucket
};

type FileHistory = {
  created: { commit: string; date: string }; // first commit touching the file, ISO 8601
  updated: { commit: string; date: string }; // last commit touching the file
};
```

`git` and `history` are plain data. Author names and emails are never read. They are left out when
the config is not in a git work tree, `git` is not installed, or there are no commits yet; nothing
fails. The values are read again on every build, so `build --watch` stays current after a commit.

`recontent` exports a helper to link to the source:

```ts
import { sourceUrl } from "recontent";

sourceUrl(ctx.git, component.sourceFilePath, component.line);
// https://github.com/acme/ds/blob/<commit>/src/button.tsx#L12
```

It returns `undefined` without a known web remote, and for files outside the repository or in
`node_modules`.

## EmittedFile

```ts
type EmittedFile = {
  path: string;
  content: string;
  writeMode?: "always" | "once";
};
```

- `path` is relative to the directory containing the config: the plugin, not the CLI, owns its output
  directory (that is why built-in plugins take an `outDir`). A path that resolves outside that
  directory is refused.
- `writeMode: "always"` (the default) rewrites the file when its content changed. `"once"` creates the
  file if it does not exist and never touches it again. Use it for files the user is meant to edit.
- Two plugins emitting the same `path` is an error that names both plugins.

## PluginDiagnostic

```ts
type PluginDiagnostic = {
  severity: "error" | "warning";
  message: string;
  path?: string[]; // the token, when the diagnostic is about one
};
```

Errors and warnings are printed, in order, as `error: <message>` and `warning: <message>`. Prefix the
message with your plugin's name so users know where it came from. Errors abort the build.

## Packaging a plugin

A plugin is just a function that returns the object above, so publish it as an ordinary package
whose peer dependency is `recontent`, and call it from the config like a built-in:

```ts
import { acmeColors } from "@acme/recontent-plugin-colors";

export default defineConfig({
  tokens: { ref, system, components },
  plugins: [css({ outDir: "src/generated" }), acmeColors({ outDir: "src/generated" })],
});
```
