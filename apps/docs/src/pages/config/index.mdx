# Configuration

Configure a project in `recontent.config.ts`. Export the result of `defineConfig()` as the default export (Recontent also accepts a named `config` export).

```ts twoslash
import { defineConfig, defineReferenceTokens, defineSystemTokens, tokens } from "recontent";
import { css } from "recontent/plugins";

const ref = defineReferenceTokens({ color: { white: tokens.color("#ffffff") } });
const system = defineSystemTokens({ color: { background: ref.color.white } });

export default defineConfig({
  tokens: { ref, system },
  themes: {},
  plugins: [css({ outDir: "src/generated" })],
  logLevel: "info",
});
```

Recontent loads config files with [jiti](https://github.com/unjs/jiti), so TypeScript works with no build step. It resolves `recontent` and `recontent/plugins` from the config file's directory and honors `paths` aliases from the nearest parent `tsconfig.json`. See [config discovery](/cli#config-discovery) for accepted filenames.

## defineConfig(input)

`defineConfig` validates the input object and returns the configuration that the CLI consumes.

### `tokens`

|          |                                                                   |
| -------- | ----------------------------------------------------------------- |
| Type     | `{ ref?: TokenTree; system?: TokenTree; components?: TokenTree }` |
| Required | Yes, unless you configure [`introspection`](#introspection)       |

Pass up to three token layers from [`defineReferenceTokens`, `defineSystemTokens`, and `defineComponentTokens`](/guides/defining-tokens). Every layer is optional.

Recontent walks each tree once:

- Registers every token by its dotted path (`ref.color.blue.9`).
- Throws on empty names, names containing `.`, `{`, `}`, `:`, `;`, tabs, or newlines, names starting with `$`, or `__proto__`, `constructor`, and `prototype`. The `components` layer also rejects top-level `"ref"` and `"system"` keys.
- Prints a **warning** when sibling names differ only by letter case.
- Prints a **warning** (`Unknown token value at "…". Use tokens.color(...) instead of an anonymous value.`) and ignores non-token values such as bare strings, numbers, or plain objects.
- Throws when nesting exceeds 64 levels.

### `introspection`

|          |                                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------------- |
| Type     | `{ entry: string; tsconfig?: string; exclude?: string[]; importPath: string \| { root: string; prefix?: string } }` |
| Required | Yes, unless you configure [`tokens`](#tokens)                                                                       |

Configures React component introspection so [`recontent inspect`](/cli/inspect) and plugins read component props and transitively referenced project types (interfaces, type aliases, and enums, excluding `node_modules`). `defineConfig` throws when you omit both `tokens` and `introspection`.

```ts
export default defineConfig({
  tokens: { ref, system, components },
  introspection: {
    entry: "src/components/index.ts",
    exclude: ["ThemeProvider"],
    importPath: "@acme/ds",
  },
  plugins: [docs({ outDir: "docs" })],
});
```

| Field        | Description                                                                                                                                                                        |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entry`      | Required. Barrel file path relative to the config file. Recontent introspects every export resolving to a React component.                                                         |
| `tsconfig`   | Path to a tsconfig relative to the config file. Defaults to the nearest `tsconfig.json` above `entry`; must include `entry` (for solution-style configs, use `tsconfig.app.json`). |
| `exclude`    | Export names to skip, such as `"ThemeProvider"` or `"Dialog.Root"`.                                                                                                                |
| `importPath` | Required. Module specifier string (`"@acme/ds"`) or `{ root, prefix }` object describing how consumers import components. See [Import statements](#import-statements) below.       |

See [Introspecting components](/guides/introspecting-components) for component detection rules, subcomponents, inherited props, generics, warnings, and [when the TypeScript program builds](/guides/introspecting-components#when-it-runs).

#### Cache

Recontent caches introspection results in `.recontent/cache-<hash>.json` next to the config file:

- `.recontent/` writes its own `.gitignore` unless one already exists, so you need no entry in your root `.gitignore`.
- Recontent reuses the cache while the Recontent version, TypeScript version, `introspection` config, tsconfig, and all read source or declaration files remain unchanged.
- Recontent detects new files inside directories of project source files (such as adding `button.ts` next to `button/index.ts`), not in the config directory or dependencies.
- Pass `--no-cache` to `build`, `inspect`, or `diff` to bypass reading and writing the cache in CI or during debugging.

#### Import statements

Recontent prints an `import` statement for each component in `recontent inspect components <name>` and on its [`docs()`](/plugins/docs) page:

- Pass a string specifier (`"@acme/ds"`) for barrel imports: `import { Button } from "@acme/ds"`.
- Pass `{ root, prefix? }` when consumers import individual component files directly. Recontent builds the specifier from `prefix` plus the defining file's path relative to `root` (relative to the config file), stripping file extensions and trailing `/index`. Default exports emit default imports.

```ts
// Consumers import from the barrel (a package, or an alias of the entry)
importPath: "@acme/ds"; // import { NewCard } from "@acme/ds"

// No barrel for consumers: they import each component's own file
importPath: { root: "app/javascript" };
// app/javascript/ui/NewCard/Card.tsx, `export default` → import NewCard from "ui/NewCard/Card"
importPath: { root: "src", prefix: "@/" };
// src/ui/Badge/index.ts, named export → import { Badge } from "@/ui/Badge"
```

Components defined outside `root` (such as re-exported library components) omit an import statement. Subcomponents (`Tabs.Item`) import their root component.

### `themes`

|         |                                 |
| ------- | ------------------------------- |
| Type    | `Record<string, ThemeOverride>` |
| Default | `{}`                            |

Named themes from [`defineTheme`](/guides/working-with-themes). Plugins use the keys in selectors and export names, and every key must match `/^[A-Za-z_][\w-]*$/`.

### `plugins`

|         |                                        |
| ------- | -------------------------------------- |
| Type    | `RecontentPlugin \| RecontentPlugin[]` |
| Default | `[]`                                   |

Outputs to generate from [built-in plugins](/plugins/css) or [custom plugins](/plugin-api). Each entry must be an object with a `name` string, or `defineConfig` throws. Without plugins, `recontent build` validates tokens and prints a warning.

### `logLevel`

|         |                     |
| ------- | ------------------- |
| Type    | `"info" \| "debug"` |
| Default | `"info"`            |

Default CLI verbosity for this project. `--log-level` and `$RECONTENT_LOG_LEVEL` override it in that order. Invalid values throw.

## define\* functions

The `define*` functions turn plain object trees into typed token layers. See [Defining tokens](/guides/defining-tokens) and [Working with themes](/guides/working-with-themes) for walkthroughs.

### Layer functions

```ts
defineReferenceTokens<T>(input: T): StampTree<T, "ref">
defineSystemTokens<T>(input: T): StampTree<T, "system">
defineComponentTokens<T>(input: T): StampTree<T, "components">
```

Each function accepts a tree of plain objects whose leaves are [`tokens` factories](/config/primitives), scales, or tokens from an earlier layer. It returns a tree of identical shape with every token _stamped_ with its layer and path.

| Function                | Layer        | Path prefix | Example path          |
| ----------------------- | ------------ | ----------- | --------------------- |
| `defineReferenceTokens` | `ref`        | `ref`       | `ref.color.blue.500`  |
| `defineSystemTokens`    | `system`     | `system`    | `system.color.accent` |
| `defineComponentTokens` | `components` | none        | `button.background`   |

A stamped token preserves its type and value. Passing another stamped token (such as `ref.color.blue[500]`) creates an **alias** that records the target path so outputs preserve the reference.

Passing a layer to `defineConfig` registers its tokens (see [`tokens`](#tokens)). Calling a layer function without passing its result to `defineConfig` has no effect.

#### Layer function errors

Layer functions validate nesting depth (> 64 levels) immediately. `defineConfig` validates the naming rules listed under [`tokens`](#tokens).

### Metadata methods

Every stamped token, scale, and [`tokens.group()`](/config/scales#groups) provides three chainable methods (color tokens also provide `.alpha(value)`). Each returns a new immutable copy.

```ts
token.describe(description: string)
token.deprecate(reason?: string)
token.extend(namespace: string, data: Record<string, unknown>)
```

| Method                     | Sets                            | Notes                                                                         |
| -------------------------- | ------------------------------- | ----------------------------------------------------------------------------- |
| `.describe(text)`          | `$description`                  |                                                                               |
| `.deprecate(reason?)`      | `$deprecated`                   | Sets `true` without a reason, or the reason string.                           |
| `.extend(namespace, data)` | `$extensions[namespace] = data` | Preserves other namespaces; calling again for the same namespace replaces it. |

Tokens from `tokens.*` factories expose the same methods. On scales, metadata attaches to the scale rather than individual steps.

```ts twoslash
import { defineSystemTokens, tokens } from "recontent";

const system = defineSystemTokens({
  color: {
    surface: tokens.color("#ffffff").describe("Default page background").deprecate("Use card"),
  },
});
```

### defineTheme

```ts
defineTheme(
  tokens: TokenTree,
  overrides: PartialTree,
  options?: { extends?: ThemeOverride[] },
): ThemeOverride
```

| Parameter   | Description                                                                                              |
| ----------- | -------------------------------------------------------------------------------------------------------- |
| `tokens`    | Target token tree: a layer, a group inside a layer, or `{ ref, system }` to override multiple layers.    |
| `overrides` | Partial tree mirroring `tokens`, with raw or stamped tokens at the leaves.                               |
| `options`   | `extends`: base themes to merge in order. Later themes override earlier ones, and `overrides` wins last. |

`defineTheme` returns a `ThemeOverride` mapping dotted token paths to their overriding values (and alias targets). Register it in [`themes`](#themes), where its key sets the theme name.

```ts twoslash
import { defineReferenceTokens, defineTheme, tokens } from "recontent";

const ref = defineReferenceTokens({
  color: { background: tokens.color("#ffffff") },
});

const dark = defineTheme(ref, { color: { background: tokens.color("#18181b") } });
```

TypeScript enforces these rules on `overrides`:

- **Leaves** must match the replaced token's type, using either a raw token or a `ref`/`system` alias.
- **Keys** must exist in `tokens`; typos fail at compile time.
- **Scales** allow full replacement only with identical keys and token type.

#### defineTheme errors

An override path matching no token throws `Theme override at "<path>" does not match an existing token path.`. This runtime check catches invalid paths introduced by type casts.

## Types

```ts twoslash
import type { DefineConfigInput } from "recontent";

const input: DefineConfigInput = { logLevel: "debug", plugins: [] };
```

Recontent exports `DefineConfigInput`, `Config`, `IntrospectionConfigInput`, `LogLevel`, `ThemeOverride`, `RawToken`, `StampedToken`, `TokenScale`, `TokenGroup`, and `TokenLayer` for programmatic config generation.
