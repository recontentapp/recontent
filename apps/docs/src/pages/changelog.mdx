# Changelog

This page tracks unreleased changes and links to published releases. We publish release notes as [GitHub releases](https://github.com/recontentapp/recontent/releases) and release [`recontent`](https://www.npmjs.com/package/recontent) under version tags (for example `0.2.0`).

## Unreleased

### Breaking changes

- Removed `PluginContext.mode`. No built-in plugin read it.
- Renamed `inspect({ fileName })` to `inspect({ filename })`, matching `tailwind({ filename })`.
- Removed CSS reset emission from `stylex()` and `vanillaExtract()`. Both plugins drop the `fontFamily` and `placeholderColor` options and no longer emit `reset.gen.css` or `reset.gen.css.ts`. Delete the generated reset files and their imports.
- Theme names must now work across every output: letters, digits, underscores, and hyphens, without starting with a digit or hyphen. `defineConfig()` throws otherwise.
- Emitting two files to the same path now causes an error, even from the same plugin. For example, two `css()` instances sharing an `outDir` or a `dtcg()` theme named `tokens` fail the build.

### Added

- `contrast()` fails the build when color pairs drop below a WCAG 2.x contrast ratio in base tokens or any theme. Rules target token groups, so the check automatically covers new colors.
- `recontent inspect search <query...>` finds tokens, components, and types by name, description, usage notes, or value (such as a hex color or CSS variable) in one call.
- Component introspection via the `introspection` config option reads React component props, defaults, types, and JSDoc. It requires `importPath` for import statements.
- `recontent inspect` browses tokens, components, and types as markdown or JSON. Pass `--from` to inspect an installed design system's published snapshot.
- `docs()` documents components (with `@usage`, `@example`, `@link`, `@category`, and `@stories`), `designMD()` writes `DESIGN.md` for agents, and `inspect()` emits the snapshot that `--from` reads.
- `recontent diff` compares components and prop types in addition to tokens.
- `recontent build --check` fails when generated files are missing or out of date.
- `resolveValue(ctx, entry, theme?)` in `recontent/plugins` resolves a token value through its alias chain and theme overrides.
- `aliasChain(ctx, entry, theme?)` in `recontent/plugins` returns the alias chain from an entry to its terminal token for a given theme.
- Plugin diagnostics and errors now name the plugin and token that triggered them.

### Fixed

- `recontent diff` previously loaded base revision tokens through the working tree's tsconfig `paths` aliases, hiding or misreporting changes.
- A theme replacing a scale with tokens built from other tokens no longer drops the override.
- `build --watch` now reloads the config file after edits instead of reusing the initial config.
- `init --force` now succeeds when the config file already has identical content, and `init -c` accepts paths outside `--cwd`.
