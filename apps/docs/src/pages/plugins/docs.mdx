# Docs

`docs()` writes a catalogue of your tokens: every token with its type, value, alias, description and
deprecation, grouped by layer and scale, with a column for each theme. Use the HTML for a static page
your team can open or host, and the Markdown for repositories and agents.

```ts twoslash
// [!include ~/snippets/docs.config.ts]
```

## Options

```ts
docs(options: DocsPluginOptions): RecontentPlugin
```

| Option     | Type      | Default           | Description                                    |
| ---------- | --------- | ----------------- | ---------------------------------------------- |
| `outDir`   | `string`  | required          | Output directory, relative to the config file. |
| `html`     | `boolean` | `true`            | Write `design.html`.                           |
| `markdown` | `boolean` | `false`           | Write `design.md`.                             |
| `title`    | `string`  | `"Design tokens"` | Page and document title.                       |

At least one of `html` and `markdown` must be enabled, or `docs()` throws.

Plugin name: `recontent:docs`.

## Emitted files

| File          | Content                                                                              |
| ------------- | ------------------------------------------------------------------------------------ |
| `design.html` | A single self-contained page, with a theme switcher that swaps the displayed values. |
| `design.md`   | The same catalogue as Markdown tables.                                               |

Both list, per layer and group, the token's path, type, resolved value, the value in each theme, the
alias it points to and its description or deprecation notice:

```md
## System

### system.color

| Token                     | Type  | Value     | dark      | Notes                                  |
| ------------------------- | ----- | --------- | --------- | -------------------------------------- |
| `system.color.background` | color | `#ffffff` | `#18181b` | → `ref.color.white`<br>Page background |
```

## Components

`docs()` depends on the project's components, so the config must set
[`introspection`](/tokens/configuration#introspection); without it the build fails and names
`recontent:docs`. `design.html` gets a
**Component APIs** tab and `design.md` a `## Component APIs` section. Each component lists its
description, a deprecation notice, a props table (name, type or allowed values, default, required,
notes), an `Also accepts:` line for props inherited from libraries, and its source location.

```md
## Component APIs

### Button

Triggers an action.

Source: `src/button.tsx:12` · Updated 2025-03-01

| Prop      | Type                   | Default   | Required | Notes          |
| --------- | ---------------------- | --------- | -------- | -------------- |
| `label`   | `string`               | —         | yes      |                |
| `variant` | `"solid" \| "outline"` | `"solid"` | no       | Visual weight. |

Also accepts: `ButtonHTMLAttributes` (263 props from @types/react)
```

The output depends only on your sources and config, never on repository state, so a "generated files
are up to date" check in CI can pass. The one exception is opt-in: with
[`introspection.history`](/tokens/configuration#history), `Updated <date>` is the last commit that
touched the component's file, and committing that file changes the docs.

A prop typed with one of your own aliases shows its expansion under the type, and a generic component
shows its type parameters next to its name, as `Accordion<Value extends string>`.

If introspection fails, `docs()` fails with the error attributed to it while the other plugins
still write their files.
