# Inspect

`inspect()` writes `recontent.json`, a snapshot of your tokens, themes, and—when you configure [`introspection`](/config#introspection)—your components and types. Publish this snapshot with your package so consuming apps can run [`recontent inspect --from`](/cli/inspect#headless-design-system-consumers) without your config file or source code.

```ts twoslash
// [!include ~/snippets/inspect.config.ts]
```

Point the `recontent` field in `package.json` at the snapshot and publish it, as described in [Publishing your design system](/guides/publishing#2-publish-it-with-the-package).

## Options

```ts
inspect(options: InspectPluginOptions): RecontentPlugin
```

| Option     | Type     | Default            | Description                                   |
| ---------- | -------- | ------------------ | --------------------------------------------- |
| `outDir`   | `string` | required           | Output directory relative to the config file. |
| `filename` | `string` | `"recontent.json"` | Name of the snapshot file.                    |

Plugin name: `recontent:inspect`. It includes components whenever you configure `introspection` and works without them otherwise.

## Emitted files

| File             | Content                                                                    |
| ---------------- | -------------------------------------------------------------------------- |
| `recontent.json` | `{ schemaVersion, kind: "snapshot", themes, tokens, components?, types? }` |

The snapshot stores the same schema as [`recontent inspect --format json`](/cli/inspect#for-scripts) with no machine-specific paths. `schemaVersion` matches that JSON output.

Run [`recontent build --check`](/cli/build) in CI to keep the published snapshot in sync with your source.
