# mcp

`recontent mcp` starts a stdio [MCP](https://modelcontextprotocol.io) server that exposes tokens, components, and types to MCP hosts such as Cursor and Claude.

```bash
recontent mcp [--no-cache]
recontent mcp --from <package|file>
```

Supports the [global options](/cli#global-options) `-c`, `--cwd`, and `--log-level`.

## Producers and consumers

| Mode     | Command                                 | Reads                                                       |
| -------- | --------------------------------------- | ----------------------------------------------------------- |
| Producer | `recontent mcp`                         | The discovered config file, with its `introspection` block. |
| Consumer | `recontent mcp --from @acme/ds`         | The [snapshot](/plugins/inspect) a published package ships. |
| Consumer | `recontent mcp --from ./recontent.json` | A snapshot file. Recontent runs no project code.            |

| Option                   | Description                                                                                    |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| `--from <package\|file>` | Serve a published snapshot instead of a config. Conflicts with `-c/--config` and `--no-cache`. |
| `--no-cache`             | Neither read nor write the [introspection cache](/config#cache).                               |

`recontent mcp` exits with code `1` before it serves in two cases. The config file is missing, or `--from` names a missing package or an invalid snapshot.

## Configure a client

Add the server to the `mcpServers` of your MCP host:

```json
{
  "mcpServers": {
    "design-system": {
      "command": "npx",
      "args": ["recontent", "mcp"]
    }
  }
}
```

In an app that consumes a published design system, pass `--from`:

```json
{
  "mcpServers": {
    "design-system": {
      "command": "npx",
      "args": ["recontent", "mcp", "--from", "@acme/ds"]
    }
  }
}
```

## Tools

The server exposes read-only tools that return compact markdown. Hosts can approve calls automatically.

| Tool                         | Arguments                                            | Returns                                                                          |
| ---------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------- |
| `get_design_system_overview` | none                                                 | Themes, token counts by layer, component names, and type names.                  |
| `get_tokens`                 | `paths?`, `layer?`, `type?`, `theme?`, `deprecated?` | Token groups when called with no filters, or matching tokens with values.        |
| `list_components`            | `category?`, `deprecated?`                           | Components grouped by category, with prop counts and short descriptions.         |
| `get_components`             | `names` (required), `props?`                         | Import, usage notes, examples, props table, and referenced types.                |
| `get_component_types`        | `names?`, `deprecated?`                              | Summary list of project types, or full definitions for the requested type names. |
| `search_design_system`       | `queries` (required), `scope?`                       | Substring search across tokens, components, and types.                           |

When `--from` reads a snapshot without components, the server omits `list_components`, `get_components`, and `get_component_types`.

A lookup that matches nothing returns a tool error with the closest names, for example `Did you mean`. The agent retries with the suggestion. Invalid arguments return a tool error that names the problem.

## Reloading

The server reloads what changed before it answers the next request:

- A change to the config file or a file it imports reloads the tokens.
- A change to a component file introspects the components again.
- A change to the snapshot file reads the snapshot again.

Unchanged requests answer from memory. A config that does not load while you edit it returns a tool error, and the server recovers when you fix the file.

The server loads the config and components with the first `tools/call`, so the handshake never waits for TypeScript.

## Output streams

- **stdout** carries only JSON-RPC 2.0 messages, one per line. Recontent redirects `console.log` and `console.info` from your config file to stderr.
- **stderr** carries logs, warnings, and errors.

The server exits with code `0` when the host closes stdin, or on `SIGINT` and `SIGTERM`.
