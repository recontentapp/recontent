# diff

`recontent diff` compares your working tree's tokens and themes against an earlier git revision. When your config file sets [`introspection`](/config#introspection), `diff` also compares component APIs and referenced prop types.

```bash
recontent diff [rev] [--fail-on-breaking] [--format <format>] [--no-cache]
```

See [Catching breaking changes](/guides/diffs) for a walkthrough and GitHub Actions workflow.

## Arguments and options

| Argument / option    | Description                                                                                        |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| `[rev]`              | Git revision to compare against. Defaults to `HEAD` and must be an ancestor of `HEAD`.             |
| `--fail-on-breaking` | Exit with code `1` when the diff finds a [breaking change](/guides/diffs#what-counts-as-breaking). |
| `--format <format>`  | Output format: `markdown` (default) or `json`.                                                     |
| `--no-cache`         | Bypass reading and writing the working tree's introspection cache (`rev` never uses the cache).    |

Supports the [global options](/cli#global-options) `-c`, `--cwd`, and `--log-level`.

## Requirements

- The config file must live inside a git repository with at least one commit.
- `rev` must be a valid git revision and an ancestor of `HEAD`. Recontent enforces this because diffing executes the config file at `rev`.
- Local git history must include `rev`. In a shallow clone, fetch full history first.

`diff` extracts the tree at `rev` into a temporary directory so local imports resolve cleanly, leaving your working tree and git state untouched.

### Components

`diff` compares components automatically when your working tree configures `introspection`. If the config at `rev` lacks `introspection`, `diff` skips component comparison and adds a note. Conversely, if `rev` configures `introspection` and your working tree removes it, every component counts as removed (breaking).

To introspect `rev`, its sources must resolve dependencies (`react`, `@types/react`). Because git archives omit `node_modules`, `diff` symlinks every gitignored `node_modules` directory from your working tree into the temporary archive at matching relative paths. Install dependencies before running `diff`. If introspecting `rev` fails, `diff` exits with that error rather than silently dropping components.

Limitations:

- Gitignored files other than `node_modules` (such as uncommitted generated files) do not exist at `rev`.
- Workspace packages linked through `node_modules` resolve to their working-tree version rather than `rev`.
- Components and props have no rename detection: renaming one reports a removal plus an addition, which remains breaking.

## Output

`diff` writes results to **stdout**. In `markdown` mode, it prints `Comparing <config> against <rev>` to stderr so redirecting stdout captures clean markdown only.

- `markdown`: Emits `# Tokens`, `# Components`, and `# Types` sections with **Breaking**, **Added**, and **Changed** subsections (tokens also include a `diff` block, **Metadata**, and **Themes**). Empty sections omit themselves. When nothing differs, it prints `No changes between the working tree and <rev>.`
- `json`: Emits one JSON object containing `schemaVersion`, `kind: "diff"`, `config`, `rev`, `breaking` (boolean), `counts`, and nested diffs:

  | Field        | Contents                                                                                                                                                                            |
  | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | `counts`     | `tokens` (`added`, `removed`, `renamed`, `retyped`, `changed`, `metadata`, `breaking`), `components` and `types` (`added`, `removed`, `changed`, `breaking`), and total `breaking`. |
  | `tokens`     | `added`, `removed`, `renamed`, `retyped`, `changed`, `metadata`, and `themes`.                                                                                                      |
  | `components` | `added`, `removed`, and `changed` (`{ name, changes }` per component).                                                                                                              |
  | `types`      | Same structure for project types.                                                                                                                                                   |

  When `diff` skips components, it omits `components`, `types`, and their counts and explains why in `componentsNote`. On errors with `--format json`, `recontent diff` prints `{ schemaVersion, kind: "error", errors: [{ message }] }` to stdout.

## Exit codes

| Code | When                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------ |
| `0`  | `diff` succeeded (including breaking changes when you omit `--fail-on-breaking`).                      |
| `1`  | An error occurred, or `--fail-on-breaking` found breaking changes (`error: 2 breaking changes found`). |

See [What counts as breaking](/guides/diffs#what-counts-as-breaking).
