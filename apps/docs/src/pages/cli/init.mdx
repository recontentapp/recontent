# init

`recontent init` creates a `recontent.config.ts` with tokens and themes and no plugins. Add plugins afterwards, then run [`recontent build`](/cli/build).

```bash
recontent init <preset> [--force]
recontent init --dtcg <path>... [--force]
```

## Presets

| Preset     | Description                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------------- |
| `neutral`  | shadcn/ui "neutral" base color: OKLCH color roles, radius, shadows, light and dark.               |
| `material` | Material 3 baseline (seed `#6750A4`): tonal palettes, color roles, type scale, elevation, motion. |

## Options

| Option          | Description                                                                                  |
| --------------- | -------------------------------------------------------------------------------------------- |
| `[preset]`      | One of the presets above. Required unless you pass `--dtcg`; the two are mutually exclusive. |
| `--dtcg <path>` | Generate the config file from DTCG tokens instead. Pass multiple paths to merge them.        |
| `--force`       | Overwrite an existing config file. Without `--force`, `init` exits with code `1`.            |

`init` writes to `-c, --config` when provided, or `recontent.config.ts` in `--cwd`. Unlike other commands, `init` does not run config discovery.

## Importing DTCG tokens

Pass `--dtcg` one or more times with these inputs:

- A **resolver** file (`*.resolver.json`, or any JSON with a resolver `$schema`). Pass it as the sole source.
- One or more **token files** (`*.json`).
- **Directories**, which `init` searches recursively for `*.tokens.json`.

`init` merges multiple token files in the order you pass them. When two files define the same token with different values, the later file wins and `init` prints a warning.

```bash
recontent init --dtcg design/tokens/
recontent init --dtcg design/resolver.json -c packages/tokens/recontent.config.ts
```

How `init` maps DTCG tokens:

- Literal values become `ref` tokens. Aliases (`{color.blue}`) and composites containing aliases become `system` tokens pointing to the final `ref` token.
- Group names, descriptions, and deprecations stay intact.
- When `$type` is missing, `init` infers it from the value where possible and prints a warning.
- In a resolver, each modifier's default context merges into the base tokens. Modifiers preserve their axis names, `default`, `description`, non-default contexts, and `resolutionOrder`, using `defineThemeAxis` when needed. Plain-alias overrides reference their target `ref` token, while other overrides emit literals.

`init` skips unsupported entries and prints a warning for each:

- Unsupported token types (such as `string`).
- Colors outside hex strings and supported [color spaces](/config/primitives#color).
- Dimensions in units other than `px`, `rem`, and `em`.
- Aliases pointing to missing tokens.
- JSON pointers referencing external files.

The final summary line reports how many tokens and themes `init` imported and how many entries it skipped.

Review the generated config file before building; it is plain TypeScript ready for you to edit.
