# inspect

`recontent inspect` prints what `recontent.config.ts` defines: tokens, themes, and—when you configure [`introspection`](/config#introspection)—components and referenced types.

```bash
recontent inspect [--format <format>] [--from <package|file>] [--no-cache]
recontent inspect tokens [path...] [--type <type>] [--theme <theme>] [--deprecated] [--format <format>]
recontent inspect components [name...] [--props <names...>] [--deprecated] [--format <format>] [--no-cache]
recontent inspect types [name...] [--deprecated] [--format <format>] [--no-cache]
recontent inspect search <query...> [--format <format>] [--no-cache]
```

Supports the [global options](/cli#global-options) `-c`, `--cwd`, and `--log-level`. Every subcommand also accepts `--from` to [browse an installed design system](#headless-design-system-consumers) without a config file.

## Browsing

Start with the overview, then drill down. Each command narrows the scope so you never read an entire design system for one answer.

```bash
recontent inspect                      # counts per layer and type, themes, component names
recontent inspect tokens               # one row per group, with counts
recontent inspect tokens system.color  # the tokens at or under system.color, with values and CSS variables
recontent inspect components           # one line per component
recontent inspect components Button    # its props: type or allowed values, default, required, notes, then the types they use
recontent inspect types                # one line per type that components' props reference
recontent inspect types TabItem        # its members or values, and the types it references in turn
recontent inspect search danger        # every token, component and type that mentions "danger"
```

Every overview—even an empty one—ends with a `Next:` line suggesting the next command.

| Command                        | Without arguments         | With arguments                                                                  |
| ------------------------------ | ------------------------- | ------------------------------------------------------------------------------- |
| `inspect`                      | The overview.             | None.                                                                           |
| `inspect tokens [path...]`     | Token groups with counts. | Each path matches one token or a group (`system.color` includes children).      |
| `inspect components [name...]` | One line per component.   | Each name matches one component or family (`Tabs` includes `Tabs.Item`).        |
| `inspect types [name...]`      | One line per type.        | Each name matches a type by id or bare name, including transitively used types. |
| `inspect search <query...>`    | Requires a query.         | Searches tokens, components, and types together for every query.                |

Options for `tokens`:

| Option            | Description                                                                                                                       |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `--type <type>`   | Filter to one token type (`color`, `dimension`). Unknown types exit with an error.                                                |
| `--theme <theme>` | Show one theme or axis selection (`dark` or `brand=acme,mode=dark`) next to the default value. Unknown themes exit with an error. |
| `--deprecated`    | Show only deprecated tokens.                                                                                                      |

`components` also accepts `--props <name...>` to show selected props in full without truncation. Unknown prop names exit `2` with close suggestions, and inherited props (such as `id`) show a row naming their source.

`components` and `types` also accept `--deprecated`. A valid filter matching nothing prints an empty result and exits `0`.

`--no-cache` (on `inspect`, `components`, `types`, and `search`) bypasses reading and writing the [introspection cache](/config#cache).

### Markdown output

Default markdown output stays compact so each component fits in a few KB:

- **Tokens:** Prints path, type, value, CSS variable, notes (alias, description, deprecation), and theme overrides.
- **Components:** Prints the [import statement](/config#import-statements), source location, and a table of **own** props with project type alias expansions.
- **Inherited library props:** Summarizes external attributes (such as `ButtonHTMLAttributes`) on an `Also accepts:` line instead of listing hundreds of rows (`--format json` includes every name).
- **Shared project prop types:** Lists shared prop types (such as `BoxProps`) on `Also accepts:` unless the component itself declares that type.
- **Long unions and types:** Shows the first 12 literal union values (`… 30 more`) and truncates long unions cleanly between members. `## Types` expands referenced object types and lists remaining types on `More types:`.

A `Next:` hint points to `--props` and `inspect types` for truncated details. `--format json` never truncates output.

## Searching

`inspect search <query...>` finds items when you do not know their exact names: `"danger"`, `"tooltip"`, or a hardcoded `"#ef4444"`. Matching uses case-insensitive substrings; each argument acts as a separate query, and an item matches when **any** query hits.

- **Tokens:** Searches path, CSS variable (`--system-color-accent`), alias, description, deprecation text, and every default or themed value.
- **Components:** Searches name, category, description, usage notes, deprecation text, and own prop names and descriptions.
- **Types:** Searches id, description, usage notes, deprecation text, member names and descriptions, and literal values.

Name and path matches appear first. Markdown notes indirect matches (`· matched in usage, prop size`), and JSON includes `matchedIn` on each hit. Zero matches exits `0` and suggests close names.

Color searches match formatted output values, so `#ef4444` does not match an `oklch` or `hsl` token. Without `introspection`, `search` checks tokens only.

## Documenting components

`inspect` reads the JSDoc tags documented in [Documenting components](/guides/documenting-components).

## For agents

Markdown output lets coding agents use your design system accurately without reading source files:

- Prints exact identifiers as code uses them: token paths, CSS variables, component names, and prop names.
- Keeps answers small through progressive drill-down (`system.color`, `Select`).
- Exits `2` on unknown paths, names, types, or themes and prints suggestions on stderr so agents recover immediately:

  ```text
  error: No token or group matches "system.colr". Did you mean `system.color`?
  ```

`recontent --help` lists all commands, and `recontent inspect --help` summarizes the drill-down workflow.

## For scripts

`--format json` prints one JSON document containing **full details for the entire selection**, never a summary. For example, `recontent inspect tokens --format json` returns every token.

| Command              | Document                                                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `inspect`            | `{ schemaVersion, kind: "overview", config, tokens: { total, layers }, themes, components?, types? }` where `themes` is an array of `{ name, default, description?, contexts }` axes |
| `inspect tokens`     | `{ schemaVersion, kind: "tokens", tokens }` with `layer`, `path`, `name`, `type`, `alias?`, `description?`, `deprecated?`, `cssVar`, and `values` (`default` plus differing themes)  |
| `inspect components` | `{ schemaVersion, kind: "components", components, types }` matching [ComponentInfo](/plugin-api#componentinfo) and transitive [TypeInfo](/plugin-api#typeinfo)                       |
| `inspect types`      | `{ schemaVersion, kind: "types", types }` with selected types and transitive references                                                                                              |
| `inspect search`     | `{ schemaVersion, kind: "search", queries, tokens, components, types, suggestions? }` with full hits plus `matchedIn`, and `suggestions` only on zero hits                           |

`schemaVersion` is `"2"` and bumps only on breaking schema changes.

- **stdout** carries only the result. Logs and warnings go to stderr; `inspect components` warns only about displayed components and project-wide issues.
- With `--theme`, every token includes that theme in `values`, falling back to its default value when not overridden.
- Exit `0` indicates success (including empty `--deprecated` results). Exit `2` means no match for the requested path, name, type, or theme. Exit `1` means a broken project (bad aliases, failed introspection, or `inspect components` without `introspection`).
- With `--format json`, errors also print to stdout as `{ schemaVersion, kind: "error", errors: [{ message, input?, suggestions? }] }` so scripts never parse prose.
- The overview command is the sole exception to exit `1`: if `introspection` fails, `recontent inspect` still prints tokens and exits `0`, reporting `components: { error }` in JSON and `_Unavailable: …_` in markdown.

```bash
# Fail CI when a deprecated component is still exported
test "$(recontent inspect components --deprecated --format json | jq '.components | length')" = 0
```

## Headless (design system consumers)

Pass `--from` to browse an installed design system from its published snapshot without its config file or source (see [Publishing your design system](/guides/publishing)):

```bash
recontent inspect --from @acme/design-system            # a package: reads the "recontent" field of its package.json
recontent inspect --from ./vendor/acme/recontent.json   # a snapshot file
```

- **Package or file:** Values starting with `.` or `/`, or ending in `.json`, load a file. All other values resolve a package in `node_modules` walking up from `--cwd`, reading `package.json`'s `recontent` field relative to the package directory.
- **Mutually exclusive flags:** Combining `--from` with `-c/--config` or `--no-cache` exits with a usage error.
- **Components:** Snapshots include components only when the author configured `introspection`. Otherwise `inspect components` and `inspect types` exit `1`, while `inspect` and `inspect tokens` still work.
- **Schema compatibility:** Opening a snapshot newer than your `recontent` version prints an upgrade error.

## Cost

`inspect tokens` loads only the config file, runs instantly, and keeps working even if `introspection` fails. Other subcommands use component introspection; see [When it runs](/guides/introspecting-components#when-it-runs) and [Cache](/config#cache). Pass `--log-level debug` to inspect timings and cache hits.
