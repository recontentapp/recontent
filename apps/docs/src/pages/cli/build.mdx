# build

`recontent build` loads the config file, runs every configured plugin, and writes the emitted files.

```bash
recontent build [--watch | --check] [--no-cache]
```

## Options

| Option        | Description                                                              |
| ------------- | ------------------------------------------------------------------------ |
| `-w, --watch` | Rerun the build whenever the config file or an imported file changes.    |
| `--check`     | Write nothing; exit `1` if any generated file is missing or out of date. |
| `--no-cache`  | Neither read nor write the [introspection cache](/config#cache).         |

Supports the [global options](/cli#global-options) `-c`, `--cwd`, and `--log-level`.

## What it does

1. Load the config file and print warnings for any token tree issues.
2. Validate aliases. Broken aliases (missing targets) and circular aliases fail the build.
3. Run each plugin's `validate` hook. Any error stops the build before writing files.
4. Run each plugin's `generate` hook and write files, creating directories as needed.

Recontent runs [introspection](/guides/introspecting-components#when-it-runs) only when the config defines `introspection` and a plugin depends on components. If introspection fails, only component-dependent plugins fail with that error; token plugins still run and emit files. Requiring introspection without configuring it causes a config error; `docs()` and `designMD()` use components only when present.

Recontent skips files whose content has not changed (`Skipped … (unchanged)`) and never overwrites existing write-once files (`Skipped … (already exists)`). No plugin can write outside the config file's directory.

```text
Wrote src/generated/tokens.css
Skipped src/generated/tokens.tokens.json (unchanged)
Wrote 1 file (1 skipped)
```

With no plugins configured, `build` prints a warning and writes nothing. `--check` passes trivially in that case because there are no files to compare.

## Failures

`build` prints each error once followed by a summary and exits with code `1`:

```text
error: [recontent:stylex] generate failed: StyleX key collision: token paths "ref.a.bC" and "ref.aB.c" both flatten to "refABC". Rename one of these tokens to avoid an ambiguous generated key.
```

Warnings never fail the build.

## Watch mode

`--watch` runs an initial build and then watches for edits. It monitors the config directory, all imported local files, and introspected component or doc files. It debounces rapid edits, queues changes arriving during a build, and refreshes the watched file list after each run.

A failing rebuild prints its error and keeps watching so you can fix the config and save again. Press `Ctrl+C` to stop.

## Checking generated files in CI

`--check` runs the full build in memory without writing files. It compares each generated output against disk and exits `1` when any file differs, catching edits committed without running `recontent build`. You cannot combine `--check` with `--watch`.

- Different content reports `Stale`; a missing file reports `Missing`.
- Write-once files check existence only, because teams edit them manually.
- `--check` does not detect leftover files from older configs.
- Regular build errors (broken aliases, plugin errors, introspection failures) fail `--check` the same way.

```text
error: Stale src/generated/tokens.css
error: Missing DESIGN.md
error: check failed: 2 of 7 files out of date; run `recontent build`
```

On success, `--check` prints `7 files up to date`. Example GitHub Actions step:

```yaml
- uses: actions/checkout@v4
- run: npx recontent build --check
```
