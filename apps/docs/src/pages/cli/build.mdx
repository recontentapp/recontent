# build

Loads the config, runs every plugin and writes the files they produce.

```bash
recontent build [--watch | --check] [--no-cache]
```

## Options

| Option        | Description                                                              |
| ------------- | ------------------------------------------------------------------------ |
| `-w, --watch` | Rerun the build whenever the config file, or a file it imports, changes. |
| `--check`     | Write nothing; exit `1` if any generated file is missing or out of date. |
| `--no-cache`  | Neither read nor write the [introspection cache](/config#cache).         |

Uses the [global options](/cli#global-options) `-c`, `--cwd` and `--log-level`.

## What it does

1. Loads the config and prints a warning for each token tree problem.
2. Checks the aliases. A broken alias (the target does not exist) or a circular one is an error.
3. Runs each plugin's `validate`. If any plugin reports an error, nothing is written.
4. Runs each plugin's `generate` and writes the files, creating directories as needed.

Components are [introspected](/guides/introspecting-components#when-it-runs) only when a configured
plugin depends on them and the config has an `introspection` block. If that fails, the plugins that
depend on components fail with the error attributed to them, and the others still run and write their
files. A plugin that requires introspection in a config without it is a config error; `docs()` and
`designMD()` only use components when they are there.

A file whose content is unchanged is not rewritten (`Skipped … (unchanged)`), and a file a plugin
marks as write-once is never overwritten (`Skipped … (already exists)`). No file outside the
config's directory can be written.

```text
Wrote src/generated/tokens.css
Skipped src/generated/tokens.tokens.json (unchanged)
Wrote 1 file (1 skipped)
```

With no plugins configured, the build prints a warning and writes nothing. `--check` then passes
trivially, since there is nothing to compare.

## Failures

Each problem is printed once, followed by a summary, and the exit code is `1`:

```text
error: [recontent:stylex] generate failed: StyleX key collision: token paths "ref.a.bC" and "ref.aB.c" both flatten to "refABC". Rename one of these tokens to avoid an ambiguous generated key.
```

Warnings do not fail the build.

## Watch mode

`--watch` builds once, then waits. It watches the directories of the config, every local file
it imports, and introspected component and doc files, and rebuilds shortly after a change (changes
are debounced, and a change during a build queues another one). The set of watched files is
refreshed after each build.

A failing rebuild prints its error and keeps watching, so you can fix the config and save again.
Stop with `Ctrl+C`.

## Checking generated files in CI

`--check` runs the same build but writes nothing. It compares each file the plugins would write with
the one on disk and exits `1` if any is out of date, so CI catches a config or component edit that was
committed without rerunning `recontent build`. It cannot be combined with `--watch`.

- A file whose content differs is `Stale`; a file that does not exist is `Missing`.
- A file a plugin marks as write-once is only checked for existence, since edits to it are expected.
- Files a previous config generated and the current one no longer does are not detected.
- Every error a regular build reports (broken alias, plugin failure, introspection failure) fails the
  check the same way.

```text
error: Stale src/generated/tokens.css
error: Missing DESIGN.md
error: check failed: 2 of 7 files out of date; run `recontent build`
```

On success it prints `7 files up to date`. In GitHub Actions:

```yaml
- uses: actions/checkout@v4
- run: npx recontent build --check
```
