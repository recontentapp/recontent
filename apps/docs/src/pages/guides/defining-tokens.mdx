# Defining tokens

Declare tokens in `recontent.config.ts` with three functions, one per layer. Each function accepts a plain object tree and stamps every token with its layer and path. Later layers can then reference earlier ones with full autocomplete.

## The three layers

```ts twoslash
import {
  defineComponentTokens,
  defineReferenceTokens,
  defineSystemTokens,
  tokens,
} from "recontent";

// Raw values: the vocabulary.
const ref = defineReferenceTokens({
  color: {
    blue: tokens.colorScale({ 500: "#3b82f6", 700: "#1d4ed8" }),
    white: tokens.color("#ffffff"),
  },
  spacing: tokens.dimensionScale({ sm: "8px", md: "16px" }),
});

// Meaning: what the values are for.
const system = defineSystemTokens({
  color: {
    accent: ref.color.blue[500],
    onAccent: ref.color.white,
  },
  spacing: ref.spacing,
});

// Decisions that belong to one component.
const components = defineComponentTokens({
  button: {
    background: system.color.accent,
    foreground: system.color.onAccent,
    paddingX: system.spacing.md,
  },
});
```

Create values with the `tokens.*` factories; see the [Tokens reference](/config/primitives) for every type. Nest objects freely inside a layer because every group name becomes part of the token path.

Recontent prefixes token paths with their layer name, except in the `components` layer:

| Layer      | Example path          | CSS variable            |
| ---------- | --------------------- | ----------------------- |
| Reference  | `ref.color.blue.500`  | `--ref-color-blue-500`  |
| System     | `system.color.accent` | `--system-color-accent` |
| Components | `button.background`   | `--button-background`   |

## Aliasing across layers

Pass a token from `defineReferenceTokens` or `defineSystemTokens` as another token's value to create an **alias**, not a copy. In the example above, `system.color.accent` aliases `ref.color.blue[500]`:

- The CSS plugin emits `--system-color-accent: var(--ref-color-blue-500);`.
- A [theme](/guides/working-with-themes) overriding `ref.color.blue.500` updates every token that aliases it.
- [`recontent diff`](/guides/diffs) distinguishes an alias change from a value change.

Use a raw value (`tokens.color("#ffffff")`) when a token has no reason to reference another token. Composites alias their members the same way:

```ts twoslash
import { defineReferenceTokens, defineSystemTokens, tokens } from "recontent";

const ref = defineReferenceTokens({
  fontFamily: { sans: tokens.fontFamily("Inter, system-ui, sans-serif") },
  fontSize: { base: tokens.dimension("1rem") },
});

const system = defineSystemTokens({
  typography: {
    body: tokens.typography({
      fontFamily: ref.fontFamily.sans,
      fontSize: ref.fontSize.base,
      fontWeight: "regular",
      lineHeight: 1.5,
    }),
  },
});
```

## Scales

A scale groups tokens of one type under fixed keys, such as a spacing scale or a color scale. Create one with a `tokens.*Scale()` factory (see [Scales](/config/scales)). Plugins use scale metadata to emit typed key unions, such as `RefSpacing` in the [TypeScript plugin](/plugins/typescript).

`tokens.generateColorScale()` builds a 12-step color scale from one base color:

```ts twoslash
import { defineReferenceTokens, tokens } from "recontent";

const ref = defineReferenceTokens({
  color: { brand: tokens.generateColorScale({ base: "#2563eb" }) },
});

const accent = ref.color.brand[9]; // your base color, used verbatim
```

## Descriptions and deprecations

Every token and scale provides three chainable methods:

```ts twoslash
import { defineSystemTokens, tokens } from "recontent";

const system = defineSystemTokens({
  color: {
    surface: tokens.color("#ffffff").describe("Default page background"),
    legacyBlue: tokens.color("#0000ff").deprecate("Use color.accent"),
    brand: tokens.color("#2563eb").extend("figma", { variableId: "VariableID:1:2" }),
  },
});
```

| Method                     | Effect                                                                         |
| -------------------------- | ------------------------------------------------------------------------------ |
| `.describe(text)`          | Sets `$description`. Appears as a CSS comment and in Docs and DTCG outputs.    |
| `.deprecate(reason?)`      | Sets `$deprecated` (`true`, or your reason). Appears in DTCG and Docs outputs. |
| `.extend(namespace, data)` | Adds `$extensions[namespace]` and exports it to DTCG.                          |

Each method returns a new token, so you can chain calls.

## Naming rules

Numeric names such as `500` work cleanly. Recontent rejects a few reserved characters and names, and ignores bare values (`accent: "#2563eb"`) with a warning. See the rules in [`tokens`](/config#tokens).

## Importing existing DTCG tokens

If you already maintain DTCG token files, generate the config file instead of writing it by hand:

```bash
recontent init --dtcg tokens/
```

Literal tokens become `ref` tokens, referencing tokens become `system` tokens, and each extra theme or modifier context becomes a theme. See [`init --dtcg`](/cli/init#importing-dtcg-tokens) for accepted inputs and skipped features.
