# Working with themes

A theme defines a set of overrides on top of your base tokens. The base values form the default theme, and each additional theme replaces only the tokens it names.

## defineTheme

`defineTheme(tokens, overrides)` takes a token tree (usually the `system` layer) and a partial object that mirrors it:

```ts twoslash
import {
  defineConfig,
  defineReferenceTokens,
  defineSystemTokens,
  defineTheme,
  tokens,
} from "recontent";

const ref = defineReferenceTokens({
  color: { gray: tokens.colorScale({ 50: "#fafafa", 900: "#18181b" }) },
});

const system = defineSystemTokens({
  color: {
    background: ref.color.gray[50],
    text: ref.color.gray[900],
  },
});

const dark = defineTheme(system, {
  color: {
    background: ref.color.gray[900],
    text: ref.color.gray[50],
  },
});

export default defineConfig({
  tokens: { ref, system },
  themes: { dark },
});
```

The dark theme points `background` and `text` at other `ref` tokens, so it follows changes to the underlying scale. You can also pass a raw token such as `tokens.color("#18181b")` for a standalone value.

The key in `themes` sets the theme name. It must use letters, digits, `_`, and `-` (not starting with a digit or `-`) for CSS, and be a valid TypeScript identifier for TypeScript, vanilla-extract, and StyleX outputs. Names such as `dark` or `highContrast` work across all plugins.

### What an override can be

- **Partial overrides.** Omitted tokens keep their base values.
- **Raw tokens or aliases.** Pass `tokens.color("#18181b")` for a literal value, or `ref.color.gray[900]` to alias another token. Aliases survive as `var(--ref-color-gray-900)` in CSS, `{ref.color.gray.900}` in DTCG, and `ref` references in TypeScript. StyleX flattens aliased overrides to literals because `stylex.createTheme` requires literal values.
- **Matching types.** TypeScript checks your override tree against the target layer and catches typos, unknown keys, or mismatched types at compile time. A runtime check also rejects paths that match no token.
- **Whole scales with identical keys.** You can replace a scale (for example with `tokens.generateColorScale({ ..., appearance: "dark" })`) only when it keeps the exact original keys and type.

```ts twoslash
import { defineReferenceTokens, defineTheme, tokens } from "recontent";

const ref = defineReferenceTokens({
  color: { brand: tokens.generateColorScale({ base: "#2563eb" }) },
});

const dark = defineTheme(ref, {
  color: { brand: tokens.generateColorScale({ base: "#2563eb", appearance: "dark" }) },
});
```

### Overriding several layers

Pass multiple layers as an object with a matching overrides object. Overrides in `ref` update the base scale, and `system` overrides can reference either the new or existing `ref` tokens:

```ts twoslash
import {
  defineConfig,
  defineReferenceTokens,
  defineSystemTokens,
  defineTheme,
  tokens,
} from "recontent";

const ref = defineReferenceTokens({
  color: {
    gray: tokens.colorScale({ 50: "#fafafa", 900: "#18181b" }),
    shadow: tokens.color("#00000026"),
  },
});

const system = defineSystemTokens({
  color: { background: ref.color.gray[50], text: ref.color.gray[900] },
});

const dark = defineTheme(
  { ref, system },
  {
    ref: { color: { shadow: tokens.color("#00000066") } },
    system: { color: { background: ref.color.gray[900], text: ref.color.gray[50] } },
  },
);

export default defineConfig({ tokens: { ref, system }, themes: { dark } });
```

## How overrides resolve

Tokens that _alias_ an overridden token follow it automatically. If `system.color.accent` aliases `ref.color.blue[9]` and a theme overrides `ref.color.blue[9]`, `system.color.accent` updates without its own override. Overriding the system token directly changes only that token.

Recontent follows a theme's own aliases the same way. If a theme points `system.color.background` at `ref.color.gray[900]`, every token aliasing `background` resolves to `gray[900]` in that theme. `recontent build` reports theme aliases whose target does not exist or that form a cycle.

Each plugin emits themes in its native format:

| Output          | Single-axis (`themes: { dark }`)                                                 | Multi-axis (`themes: { brand, mode, density }`)                                                     |
| --------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| CSS, Tailwind   | `.dark { … }` (or `[data-theme="dark"]`) + `@custom-variant dark`.               | `.mode-dark`, `.density-compact` (or `[data-mode="dark"]`) in `resolutionOrder` + stacked variants. |
| vanilla-extract | Base `themeClass` + additive `darkThemeClass = style({ vars })`.                 | Base `themeClass` + per-axis maps (`brandThemes`, `modeThemes`) in `resolutionOrder`.               |
| StyleX          | `darkTheme = stylex.createTheme(vars, { … })`.                                   | Materialized combinations behind `getTheme(selection: ThemeSelection)`.                             |
| TypeScript      | `dark` constant plus `themes`, `ThemeName`, and `Theme`.                         | Base `theme` plus `resolveTheme(selection: ThemeSelection)` and `Theme`.                            |
| DTCG            | `tokens.resolver.json` + `tokens.tokens.json` + `themes/dark.tokens.json` delta. | `tokens.resolver.json` + `tokens.tokens.json` + `themes/<axis>-<context>.tokens.json` deltas.       |
| Contrast        | Checks base tokens and every theme.                                              | Checks the Cartesian product of color-affecting axes, skipping non-color axes like `density`.       |
| Docs            | Header theme popover swapping values and highlighting overrides.                 | Header theme popover with a selector per axis, updating live across any combination.                |
| DESIGN.md       | Single `## Themes` table.                                                        | One `### <axis>` table per axis plus a `resolutionOrder` note.                                      |

## Which layer to override

Both patterns work because aliases follow overrides. Choose the layer that matches what changes:

- **Override `ref` scales when the palette changes.** A dark scale (`appearance: "dark"`) updates every system token that aliases it in one override.
- **Override `system` tokens when only the mapping changes.** To point `background` at a different color in dark mode while keeping the same `ref` scale, override `background` directly.

## Switching at runtime

For CSS and Tailwind, theme blocks default to a class selector. Add the class to the root element:

```html
<html class="dark"></html>
```

To use an attribute selector instead, set `themeSelector: "attribute"` on the plugin. For a single axis, the attribute defaults to `data-theme` (or `data-<axis>` for a named axis), and you can customize it with `themeAttribute`:

```ts
css({ outDir: "src/generated", themeSelector: "attribute", themeAttribute: "data-mode" });
```

```html
<html data-mode="dark"></html>
```

Tailwind also generates a `@custom-variant` per context, so you can write `dark:bg-surface` (or stack `mode-dark:density-compact:p-2` with multiple axes). See the [Tailwind plugin](/plugins/tailwind#theme-variants).

For vanilla-extract, `themeClass` defines the base contract and theme classes apply partial overrides on top—compose them together (``className={`${themeClass} ${dark ? darkThemeClass : ""}`}``).

To follow a user's OS preference, set the class or attribute from `matchMedia("(prefers-color-scheme: dark)")` in your app. Recontent omits `@media` rules so theme selection stays under your control.

## Orthogonal axes (brand, mode, density)

Design systems often vary along independent dimensions—for example **brand** (`acme`, `globex`), **color mode** (`dark`, `highContrast`), and **density** (`compact`). Instead of manually declaring every combination (`acmeDarkCompact`, …), group themes by axis in `defineConfig`:

```ts twoslash
import {
  defineConfig,
  defineReferenceTokens,
  defineSystemTokens,
  defineTheme,
  defineThemeAxis,
  tokens,
} from "recontent";

const ref = defineReferenceTokens({
  color: {
    brand: tokens.color("#2563eb"),
    gray: tokens.colorScale({ 50: "#fafafa", 900: "#18181b" }),
  },
  spacing: tokens.dimensionScale({ sm: "8px", md: "16px" }),
});

const system = defineSystemTokens({
  color: { accent: ref.color.brand, background: ref.color.gray[50] },
  spacing: ref.spacing,
});

const acme = defineTheme(ref, { color: { brand: tokens.color("#7c3aed") } });
const dark = defineTheme(system, { color: { background: ref.color.gray[900] } });
const compact = defineTheme(system, {
  spacing: tokens.dimensionScale({ sm: "4px", md: "8px" }),
});

export default defineConfig({
  tokens: { ref, system },
  themes: {
    brand: defineThemeAxis({ default: "core", description: "Brand identity", contexts: { acme } }),
    mode: defineThemeAxis({ default: "light", contexts: { dark } }),
    density: { compact },
  },
});
```

- **Plain objects or `defineThemeAxis`.** An axis can be a plain `{ context: theme }` object (default context `"default"`) or a `defineThemeAxis({ default, description, contexts })` call when you want a named default context or DTCG modifier description.
- **Resolution order.** Axes apply in the object key order of `themes` (matching DTCG 2025.10 `resolutionOrder`). When two active axes override the same token, the later axis wins across CSS, vanilla-extract, TypeScript, StyleX, Contrast, and DTCG resolvers.
- **Composing in HTML/CSS.** Add one class or `data-<axis>` attribute per active axis: `<html class="brand-acme mode-dark density-compact">` or `<html data-brand="acme" data-mode="dark" data-density="compact">`.
