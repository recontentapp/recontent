# Using plugins

Tokens in a config file do nothing until plugins emit files from them. Import built-in plugins from `recontent/plugins` and list them in `defineConfig`:

```ts twoslash
import { defineConfig, defineReferenceTokens, tokens } from "recontent";
import { css, dtcg, typescript } from "recontent/plugins";

const ref = defineReferenceTokens({
  color: { white: tokens.color("#ffffff") },
});

export default defineConfig({
  tokens: { ref },
  plugins: [
    css({ outDir: "src/generated/css" }),
    typescript({ outDir: "src/generated/ts" }),
    dtcg({ outDir: "tokens" }),
  ],
});
```

Each plugin has its own reference page under **Plugins reference** in the sidebar.

## outDir

Almost every plugin takes an `outDir` relative to the config file's directory (not your current working directory). A plugin cannot write outside that directory.

Two plugins cannot emit the same file path. If they collide, the build fails and names both plugins. Give each plugin its own `outDir` or `filename`; note that `typescript()` and `typescriptNative()` both default to `tokens.ts`.

## Order

Plugins run in the order listed in `plugins`. Custom plugins can pass `enforce: "pre"` or `"post"` to run earlier or later (see [Writing a plugin](/plugin-api)). Built-in plugins are independent, so their order does not affect output.

## What a build does

A build loads the config file, validates aliases, runs each plugin's validation, and only then writes files. Any error stops the build **before writing any file**. See [`build`](/cli/build#what-it-does) for the exact steps.

Recontent skips unchanged files so file watchers and HMR stay quiet.

## Rebuilding while you work

`recontent build --watch` rebuilds whenever the config file, an imported file, or an introspected component or doc file changes. Run it alongside your dev server (this example uses `concurrently`):

```json [package.json]
{
  "scripts": {
    "dev": "concurrently \"recontent build --watch\" \"vite\"",
    "build": "recontent build && vite build"
  }
}
```

Because generated files are ordinary source files, Vite, Storybook, or your framework detects changes through standard HMR. A failed rebuild prints the error and keeps watching.

## Committing the output

You can commit or gitignore generated files. Commit them when you want output diffs visible in pull requests or when consumers cannot run the CLI. Otherwise ignore them and run `recontent build` during install or build. In either case, run `recontent build` in CI to catch stale configs.
