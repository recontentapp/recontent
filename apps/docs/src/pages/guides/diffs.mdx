# Catching breaking changes

`recontent diff` compares your working tree's tokens against an earlier git revision and reports every change. Use it in pull requests to review token updates and block breaking removals or renames. When your config file sets [`introspection`](/config#introspection), `diff` also compares component props and referenced types.

```bash
recontent diff main
```

````md
# Tokens

## Breaking (2)

- **renamed** `system.color.bg` -> `system.color.background` (color, alias -> ref.color.gray.50)
- **removed** `system.color.legacyBlue` (color #0000ff)

## Added (1)

- `system.color.accent` (color, alias -> ref.color.blue.9)

## Changed (1)

```diff
# ref.color.gray.900
- #18181b
+ #09090b
```
````

The revision defaults to `HEAD`, so running `recontent diff` with no arguments shows uncommitted changes.

## What counts as breaking

A change counts as **breaking** when existing code using a token stops working:

| Change                                                   | Breaking |
| -------------------------------------------------------- | -------- |
| Removing a token                                         | Yes      |
| Renaming a token (same type and value, new path)         | Yes      |
| Changing a token's type (`dimension` to `number`)        | Yes      |
| Removing a theme                                         | Yes      |
| Adding a token                                           | No       |
| Deprecating a token or editing its description           | No       |
| Changing a token's value or alias                        | No       |
| Adding a theme or adding, editing, or dropping overrides | No       |

Recontent detects renames by pairing one removed token with one added token that shares the same type and value (or alias). When several tokens share a value, Recontent reports an ambiguous removal and addition instead, which still counts as breaking.

### Components and types

A change to a component or referenced type counts as **breaking** when consumer code stops type-checking:

| Change                                                                           | Breaking |
| -------------------------------------------------------------------------------- | -------- |
| Removing a component or type                                                     | Yes      |
| Changing a component's `import` statement                                        | Yes      |
| Removing a prop or type member                                                   | Yes      |
| Adding a required prop or making an optional prop required                       | Yes      |
| Removing a value from a literal union, enum, or union type                       | Yes      |
| Changing a prop's type in any way other than widening a union                    | Yes      |
| Changing a non-object, non-union type definition or renaming an enum member      | Yes      |
| Dropping props inherited from another type                                       | Yes      |
| Adding a type parameter without a default, removing one, or changing constraints | Yes      |
| Changing a type's kind (`interface`, `type`, `enum`)                             | Yes      |
| Adding a component, type, or optional prop                                       | No       |
| Widening a union or literal union                                                | No       |
| Making a required prop optional                                                  | No       |
| Renaming a type parameter, adding one with a default, or changing its default    | No       |
| Changing a default value or toggling `@deprecated`                               | No       |

Recontent treats any unclassifiable prop type change as breaking. It ignores descriptions, line numbers, formatting, and file moves (unless `importPath` uses `{ root, prefix }` and the move changes the `import` statement). Types appear in the diff only while component props reference them, so removing the last referencing prop reports the type as removed.

## Failing a build

Pass `--fail-on-breaking` to exit with code `1` when `diff` finds any breaking change:

```bash
recontent diff origin/main --fail-on-breaking
```

Without this flag, `diff` exits `0` even when breaking changes exist. Errors such as an invalid revision or missing config file always exit `1`.

## GitHub Actions

`diff` reads your config file at the base revision, so git must have that commit in local history.

:::warning
With a shallow clone, `diff` fails with "this looks like a shallow clone missing the required history". Set `fetch-depth: 0` in `actions/checkout` (or run `git fetch --unshallow` locally) before running `diff`.
:::

```yaml [.github/workflows/tokens.yml]
name: Tokens

on: pull_request

jobs:
  diff:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0 # `diff` needs the base branch's history

      - uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - run: npm ci

      - name: Diff tokens against the base branch
        run: npx recontent diff "origin/${{ github.base_ref }}" > token-diff.md

      - name: Comment on the pull request
        run: gh pr comment "${{ github.event.pull_request.number }}" --body-file token-diff.md
        env:
          GH_TOKEN: ${{ github.token }}

      - name: Fail on breaking changes
        run: npx recontent diff "origin/${{ github.base_ref }}" --fail-on-breaking > /dev/null
```

Recontent writes markdown to stdout and progress messages to stderr, so redirecting stdout produces a clean PR comment file. Omit the comment step if you only need a CI gate.

## Only ancestors of HEAD

Diffing executes the config file from the target revision. To avoid executing code from untrusted branches, `diff` accepts only ancestors of `HEAD`. It rejects unmerged branches with an explanation; merge or rebase first.

## Machine-readable output

Pass `--format json` to print a single JSON document instead of markdown:

```bash
recontent diff main --format json
```

The JSON object contains `config`, `rev`, `breaking`, `counts`, and the nested `tokens` (including theme changes), `components`, and `types` diffs. See the [`diff` reference](/cli/diff#output) for the exact schema.
