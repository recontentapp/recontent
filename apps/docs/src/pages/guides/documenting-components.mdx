# Documenting components

Usage notes, examples and deprecations belong next to the code they describe. Recontent reads the
JSDoc comments of the components, props and types that [introspection](/guides/introspecting-components)
finds, and shows them wherever someone (or an agent) needs to use a component without opening its source.

## Tags

Besides the description, `@deprecated` and `@default`, six tags help:

| Tag                         | On                    | Effect                                                                                                                                                                                                                                                                                                |
| --------------------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@example`                  | component, prop, type | One example per tag. `<caption>Title</caption>` titles it, and surrounding code fences are removed. A relative path (`./Button.basic.tsx`) uses the file's content verbatim, so the example is typechecked with your code. Props show one-line examples in `inspect`; the rest is in `--format json`. |
| `@usage`                    | component, type       | When to use it and when not to, in markdown. Kept out of the description, so that summaries stay one line. A relative path (`./Button.usage.md`) uses the file's content verbatim.                                                                                                                    |
| `@link`                     | component, prop, type | An external page: `@link <caption>Figma</caption> https://figma.com/docs/button`. The caption is optional; only `http(s)` URLs are kept, the others are reported as warnings. Listed in `externalLinks`, and shown on the component's page in the [docs plugin](/plugins/docs).                       |
| `{@link Name}`              | anywhere in the text  | Names a component or a type. It is listed in `links`. Anything else stays plain text.                                                                                                                                                                                                                 |
| `@deprecated Use {@link X}` | component, prop, type | The first link is the `replacement`, shown as `deprecated → X` in summaries.                                                                                                                                                                                                                          |
| `@experimental`             | component, prop, type | Marks it as experimental, with an optional note. Shown as a callout, and as `experimental` in summaries.                                                                                                                                                                                              |
| `@category`                 | component             | Groups components in `inspect components` and in the docs navigation. Components without one come last.                                                                                                                                                                                               |

```tsx
/**
 * Triggers an action.
 *
 * @usage Prefer a link when the click only navigates.
 * @link <caption>Figma</caption> https://figma.com/docs/button
 * @example <caption>Basic</caption>
 * <Button label="Save" />
 * @example <caption>With an icon</caption> ./Button.icon.tsx
 * @category Actions
 */
export function Button(props: ButtonProps) {}

/** @deprecated Use {@link Button} instead. */
export function PrimaryButton(props: ButtonProps) {}
```

## Where each tag shows up

| Tag             | `recontent inspect`                   | `design.html`             | `DESIGN.md`                       | `recontent diff`                  |
| --------------- | ------------------------------------- | ------------------------- | --------------------------------- | --------------------------------- |
| Description     | Yes                                   | Yes                       | First paragraph, per component    | Ignored                           |
| `@default`      | Yes, in the props table               | Yes, in the props table   | No                                | A changed default is not breaking |
| `@deprecated`   | Yes, with the replacement             | Yes, as a notice          | Under "Do's and Don'ts"           | A new deprecation is not breaking |
| `@experimental` | Yes                                   | Yes, as a notice          | No                                | Ignored                           |
| `@usage`        | Yes                                   | Yes, rendered as markdown | No, points to `recontent inspect` | Ignored                           |
| `@example`      | Yes, one-line examples only for props | Yes, as tabs              | No, points to `recontent inspect` | Ignored                           |
| `@link`         | Yes, as a list of links               | Yes, as tags              | No                                | Ignored                           |
| `@category`     | Groups `inspect components`           | Groups the navigation     | No                                | Ignored                           |

Examples, usage, links and category are documentation, not API: [`recontent diff`](/cli/diff) does not
report them.
